# Workflow Canvas Backendization MVP

## 1. 文档目标

本文档定义当前阶段“画布、文件、执行、任务历史后端化”的统一边界，作为后续接口、持久化、调度与前端接入的唯一基线。

本轮目标不是做完整工作流平台，而是先完成以下最小闭环：

- 后端成为 `Workflow` 画布的真实持久化来源
- 画布引用的文件在进入画布后立即进入上传调度
- 执行与任务历史按账户归属、按画布聚合保存
- 文件物理内容走后端本地内容寻址存储
- 前后端在性能约束上采用统一基线，避免后续返工

## 2. 范围与边界

### 2.1 本轮纳入范围

- `Workflow` 作为画布持久化实体继续沿用
- `projectId` 字段继续保留，但本轮不扩展复杂项目域能力
- 画布完整节点、连接、视口、元数据持久化到后端
- 画布内文件引用、执行记录、任务历史、事件流统一纳入后端
- 文件进入画布即触发上传调度
- 执行任务历史按 `execution task` 粒度落库与查询

### 2.2 本轮明确不做

- 旧本地历史数据兼容迁移
- 画布多人协作与冲突合并
- 画布版本回滚
- 项目成员、多租户、复杂 RBAC
- 删除节点或解除绑定时自动删除物理文件
- 独立后台运营视图

## 3. 领域真源与账户归属

### 3.1 画布真源

- 后端正式承担画布真源职责
- `Workflow` 是画布持久化实体，而不是仅用于执行模板引用
- 前端本地 JSON 导入导出仅保留为辅助能力，不再是主持久化路径

### 3.2 账户绑定关系

- `workflow` 绑定 `ownerUserId`
- `file asset` 绑定 `ownerUserId`
- `execution run` 绑定 `ownerUserId`
- `execution task` 绑定 `ownerUserId`
- `task event` / `task history` 通过 `task` 和 `workflow` 间接绑定到账户

权限基线：

- `member` 仅能查看和操作自己的 workflow、file、run、task、event
- `admin` 可跨账户查看和管理上述数据

### 3.3 Workflow 与 projectId

- `workflowId` 是画布主标识
- `projectId` 继续保留为轻量级分组字段
- 当前不建立独立 `project` 聚合根，不做项目成员体系

## 4. 画布、文件、执行、历史之间的关系

### 4.1 画布保存内容

后端保存的 `Workflow` 至少包含：

- 画布基础信息：`workflowId`、`projectId`、`ownerUserId`、标题、描述、时间戳
- 画布结构：所有节点、连接、分组、视口、元数据
- 画布文件引用：节点内引用的后端文件信息，而不是浏览器内存 `File`
- 保存状态摘要：最近保存时间、最近执行时间、最近任务摘要

### 4.2 文件绑定规则

- 节点引用文件时，最终保存到画布中的应是后端文件引用
- 解除节点与文件的绑定时，仅解除引用关系，不删除物理文件
- 相同物理内容可以被多个画布、多个节点、多个任务复用

### 4.3 任务历史粒度

- 每个 `execution task` 形成一条主历史记录
- 历史查询默认按 `workflowId` 聚合
- `execution run` 作为一次执行入口记录
- `execution task` 作为可调度、可重试、可分页查询的历史单元

## 5. 文件即时上传与优先级调度

### 5.1 总体流程

文件进入画布后的标准流程如下：

1. 前端为文件生成本地待上传记录
2. 前端异步计算文件哈希
3. 前端调用后端预检接口，提交文件摘要信息
4. 若后端已存在相同内容，则直接复用已有 `fileId`
5. 若后端不存在相同内容，则进入二进制上传
6. 上传完成后，画布节点引用替换为后端文件引用
7. 画布保存时仅保存后端文件引用与必要展示元数据

### 5.2 任务触发优先级

- 文件一旦进入画布就开始上传，不等待手动保存
- 若用户在仍有未上传文件时触发任务执行，调度器必须提升该任务依赖文件的上传优先级
- 非当前任务所需文件可继续排队或延后上传
- 前端需要具备“哈希队列 + 上传队列 + 执行前文件就绪检查”的调度能力

### 5.3 去重原则

- 去重基于文件内容哈希，而不是文件名
- 同一账户重复添加相同内容文件时，不重复上传
- 不同账户添加相同内容文件时，物理内容可复用，但逻辑文件归属仍分离
- 节点解除绑定或画布删除时，不自动删除 blob

## 6. 二进制上传协议基线

### 6.1 协议选择

- 主上传链路采用二进制上传
- 不再以 base64 JSON 作为主存储协议
- JSON 仅承载文件摘要、上传状态、逻辑绑定信息

### 6.2 推荐协议步骤

1. `POST /files/register`
   传入 `sha256`、`size`、`mimeType`、`originalName`、可选 `workflowId`
2. 后端返回：
   - 已命中：直接返回可复用 `fileId`
   - 未命中：返回待上传标识或上传目标
3. `POST /files/upload`
   传输原始二进制内容
4. 后端完成 blob 落盘、逻辑文件记录和 workflow 绑定更新

### 6.3 返回语义

- 文件注册接口必须区分：
  - `deduplicated`
  - `upload_required`
  - `already_bound`
- 上传完成后必须返回最终可持久化的后端文件引用

## 7. 内容寻址与本地存储规则

### 7.1 内容寻址

- 物理文件按 `sha256` 进行内容寻址
- 推荐目录规则：
  - `storage/blobs/{sha256-prefix}/{sha256}.{ext}`
- `sha256-prefix` 用于降低单目录文件数量

### 7.2 逻辑层与物理层分离

- blob 层负责去重与落盘
- file asset 层负责用户可见 ID、显示名、权限归属、画布绑定
- workflow 层负责保存节点与文件引用关系

## 8. 分片存储布局基线

当前阶段采用 JSON Store 风格，但必须按聚合和访问热点做分片，避免单文件无限膨胀。

推荐布局如下：

```text
backend/data/
  workflows/
    index.json
    {workflowId}/
      workflow.json
      files.json
      tasks.json
      events/
        {taskId}.jsonl
  executions/
    runs/
      {runId}.json
  files/
    files-store.json
  accounts-store.json

backend/storage/
  blobs/
    {sha256-prefix}/
      {sha256}.{ext}
```

说明：

- `workflows/index.json` 只保存画布摘要，供列表查询
- `workflow.json` 保存完整画布结构
- `files.json` 保存该画布关联文件摘要与引用
- `tasks.json` 保存该画布的任务摘要列表
- `events/{taskId}.jsonl` 保存单任务事件流
- `executions/runs/{runId}.json` 保存执行入口记录与汇总信息

## 9. 任务历史与事件流策略

### 9.1 历史聚合维度

- 前端任务历史查询主入口按 `workflowId` 聚合
- 运行链路保留 `runId` 维度
- 列表接口默认返回 task 级摘要，不直接返回完整事件流

### 9.2 事件流写入方式

- 任务事件使用 `JSONL` 追加写
- 每个 `taskId` 独立事件文件
- 事件写入不得因为大对象重写而阻塞其他任务

### 9.3 任务摘要字段

每条 task summary 至少包含：

- `taskId`
- `runId`
- `workflowId`
- `ownerUserId`
- `nodeId`
- `nodeType`
- `groupId`
- `status`
- `inputSummary`
- `outputSummary`
- `startedAt`
- `completedAt`
- `durationMs`

## 10. 性能基线

### 10.1 前端性能基线

- 文件哈希计算应放入 Worker，不阻塞主线程
- 哈希并发建议默认值：`2`
- 上传并发建议默认值：`2`
- 任务依赖文件可提升优先级，但不能打破单飞约束
- 画布自动保存需 `debounce`，建议区间：`800ms - 1500ms`
- 同一画布保存采用单飞，避免并发写冲突
- 画布列表页只拉摘要，不拉完整节点数据

### 10.2 后端性能基线

- 画布、文件、任务、事件至少采用分片锁，不使用全局大锁
- 关键 JSON 写入使用临时文件 + rename 原子替换
- 事件流使用追加写，避免重写全量任务文件
- 画布列表、任务列表必须支持分页或窗口化读取
- workflow 列表接口仅返回摘要，不返回完整 `workflow.json`
- run/task 查询默认先走摘要文件，详情按需读取

## 11. 一致性与异常处理基线

- 画布保存与文件上传不要求单事务强一致，但必须保证引用状态可恢复
- 文件上传中断后，应保留待补传状态，不能污染已完成 blob
- 任务创建前必须校验依赖文件是否已存在后端引用
- 若当前任务依赖文件未完成上传，应先触发优先上传，再进入执行创建

## 12. 本轮实施约束

- 当前阶段不兼容旧本地历史数据
- 当前阶段不做画布冲突合并
- 当前阶段不实现引用计数驱动的物理文件删除
- 当前阶段前端任务历史页面可以先保留现状，优先流出后端查询接口
