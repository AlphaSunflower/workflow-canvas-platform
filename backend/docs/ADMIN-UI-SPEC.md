# 后台前端规范

## 1. 文档目的

本文档定义独立后台前端的页面结构、展示重点、权限范围和一期范围。

后台前端目录固定放在：

- `backend/admin-web/`

## 2. 后台定位

后台前端是给管理员使用的运营与排查工具，不是给普通用户编辑画布使用的界面。

后台前端重点是：

1. 观察当前系统健康状态
2. 查看执行历史与失败重试
3. 管理用户
4. 管理平台 Key 池
5. 查看存储与负载

## 3. 必须页面

### 3.1 登录页

用途：

- 管理员登录后台

### 3.2 总览页

必须展示：

- 当前排队数
- 当前执行中数量
- 今日完成数量
- 今日失败数量
- 已启用 Key 数量
- 熔断 Key 数量
- 存储总量

建议同时展示：

- 平台负载分布
- 任务状态分布

### 3.3 用户管理页

必须支持：

- 创建用户
- 启用/禁用用户
- 重置用户密码
- 查看用户执行历史

### 3.4 执行历史页

必须支持按以下维度筛选：

- 用户
- 执行编号
- 任务编号
- 节点类型
- 状态
- 时间范围

### 3.5 执行详情页

必须展示：

- 执行主记录信息
- 任务列表
- 输入文件
- 输出产物
- 重试历史
- 事件流
- 最终错误
- Key 占用信息

### 3.6 Key 池管理页

必须展示：

- 平台
- 当前状态
- 最大并发
- 当前占用
- 优先级
- 失败次数
- 熔断状态

必须支持：

- 新增 Key
- 修改 Key 元数据
- 启用 Key
- 禁用 Key

## 4. 界面重点

后台界面应优先强调：

1. 当前系统是否健康
2. 哪些任务失败了
3. 失败任务重试到了第几次
4. 哪个平台负载高
5. 哪些 Key 已熔断

而不是复杂的业务配置页面。

## 5. 数据展示最小要求

### 5.1 总览卡片

建议包含：

- 排队数
- 执行中数量
- 今日完成数
- 今日失败数
- 已启用 Key 数
- 熔断 Key 数

### 5.2 执行列表

建议列：

- `runNo`
- 用户
- 节点类型
- 任务数量
- 状态
- 创建时间
- 完成时间

### 5.3 任务详情

建议展示字段：

- `taskNo`
- `runNo`
- 当前状态
- 当前尝试次数
- 最大尝试次数
- 最近错误
- 输入文件列表
- 输出文件列表
- 事件时间线

### 5.4 Key 池列表

建议列：

- 平台
- Key 标签
- 状态
- 最大并发
- 当前占用
- 失败次数
- 熔断状态

## 6. 权限规则

- 只有 `admin` 可以访问后台前端
- 普通用户不能访问后台路由

## 7. 一期不做的内容

一期不要求：

- 自定义报表
- 告警中心
- 计费页面
- 按项目/团队切片的后台视图
