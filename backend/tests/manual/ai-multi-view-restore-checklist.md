# 多视角修复节点一期手工联调清单

## 1. 联调前准备

- 已在 `backend/config/backend.config.json` 中填写真实 `providers.runninghub.apiKey`
- API 服务可启动
- Worker 服务可启动
- 前端已连接到真实后端接口
- 已准备至少 2 组测试输入：
  - 渲染图
  - 原视角参考图
- `paths.providerSnapshotDir` 已开启并可写入

## 3. 手工检查项

### 3.1 文件注册链路

- 前端执行前先上传或注册两张输入图
- 后端成功返回 `fileId`
- 创建执行时每个 group 都带上 `renderFileId` 和 `referenceFileId`

### 3.2 单组真实成功链路

- 提交输入组 1
- 任务进入排队或执行状态
- 渲染图上传成功
- 参考图上传成功
- RunningHub 创建成功
- 查询结果 V2 命中 `nodeId = 127`
- 后端下载结果图成功
- 最终结果图回写到前端节点

### 3.3 grouped 并发链路

- 一次提交至少 2 个 group
- 后端为多个 group 创建独立任务
- 多个 group 可以并发执行
- 一个 group 的执行不会阻断另一个 group 完成

### 3.4 上传失败链路

- 人为制造上传失败场景
- 观察是否写入明确错误
- 观察是否触发自动重试
- 三次失败后是否进入最终失败

### 3.5 创建失败链路

- 人为制造 RunningHub 创建失败场景
- 观察 `promptTips` 与错误信息是否可查
- 观察是否按规则重试或最终失败

### 3.6 promptTips 异常链路

- 人为制造 `promptTips.result = false`
- 或 `promptTips.error` 非空
- 或 `promptTips.node_errors` 非空
- 观察是否被识别为创建阶段异常

### 3.7 查询结果为空链路

- 人为制造结果为空场景
- 观察轮询是否持续进行
- 观察超时或失败后是否写入明确错误

### 3.8 输出节点 127 校验链路

- 成功场景下确认结果优先命中 `nodeId = 127`
- 异常场景下确认未命中 127 且多个结果时会失败

### 3.9 查询与结果回显

- 可查询 run 级状态
- 可查询 task 级状态
- 可查询步骤事件
- 可查询 `renderFileId / referenceFileId`
- 可查询 `workflowId / workflowTemplateKey`
- 可查询 `providerTaskId / providerClientId`
- 可查询最终结果文件引用
