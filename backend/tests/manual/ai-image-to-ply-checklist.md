# 图片转模型节点一期手工联调清单

## 1. 联调前准备

- 已在 `backend/config/backend.config.json` 中填写真实 `providers.runninghub.apiKey`
- API 服务可启动
- Worker 服务可启动
- 前端已连接到真实后端接口
- 已准备至少 2 组测试输入图片
- `paths.providerSnapshotDir` 已开启并可写入

### 输入组 2

## 3. 手工检查项

### 3.1 文件注册链路

- 前端执行前先上传或注册输入图片
- 后端成功返回 `fileId`
- 后端不依赖前端本地路径即可定位输入文件

### 3.2 单组真实成功链路

- 提交输入组 1
- 任务进入排队或执行状态
- RunningHub 上传成功
- RunningHub 创建成功
- 查询结果 V2 返回 `ply` 文件
- 后端下载 `ply` 成功
- 最终结果可回写到前端节点

### 3.3 grouped 多任务并发链路

- 一次提交至少 2 个 group
- 后端为多个 group 创建独立任务
- 多个 group 可并发执行
- 一个 group 的执行不会阻塞另一个 group 的完成

### 3.4 上传失败链路

- 人为制造 RunningHub 上传失败场景
- 观察是否写入明确错误
- 观察是否按统一策略触发自动重试
- 三次均失败时是否进入最终失败

### 3.5 创建失败链路

- 人为制造 RunningHub 创建失败场景
- 观察是否记录 `providerTaskId / clientId / promptTips` 相关信息
- 观察是否按统一策略触发自动重试或最终失败

### 3.6 promptTips 异常链路

- 人为制造 `promptTips.result = false`
- 或 `promptTips.error` 非空
- 或 `promptTips.node_errors` 非空
- 观察是否被尽早识别为创建阶段异常

### 3.7 查询结果为空链路

- 人为制造 RunningHub 查询结果为空场景
- 观察轮询是否持续进行
- 观察超时或失败后是否写入明确错误

### 3.8 ply 下载与落库链路

- 成功返回 `results[0].fileUrl`
- `results[0].fileType = ply`
- 后端下载成功
- 后端文件资产可查询到 `ply` 文件
- 前端最终输出可使用该结果文件

### 3.9 查询与结果链路

- 可查询 run 级状态
- 可查询 task 级状态
- 可查询步骤事件
- 可查询最终结果文件引用
- 失败时可查询错误码、错误信息、attempt 记录
